# G2: telemetry-seeded mapping in wasm (gate)

2026-11-08. **Result: the colmap-wasm route works; all G2 criteria pass in Node, in a module
worker in headless Chrome on the laptop, and in Chrome on the win11 machine.** The three runs
produce byte-identical verified geometry and models. The `ba.c` fallback is not needed.
Criterion 3 used browser *matching* of the native descriptors; the >= 90% check with
browser-*extracted* features stays pending until stage 3. The REVIEW-g2.md round 1 fixes are at
the end.

## The fork

Upstream: github.com/obraia/colmap-wasm at `ec1f1bc2ecac44d7d110edef9eb297419be57cfb`
(2026-10-20, COLMAP 4.2.1 at `bd1fcf65`). Working clone `$WEBSPLAT_DATA/colmap-wasm-fork`
(branch `websplat`); patch series in `app/src/stages/map/colmap-wasm-patches/`:

1. `native: build with the system emscripten/cmake/ninja`: `COLMAP_WASM_SYSTEM_TOOLCHAIN=1`
   skips the emsdk/venv set-up in fetch.sh/build.sh, `JOBS` for parallel builds. The
   distribution emscripten 3.1.69 builds everything (upstream pins emsdk 6.0.12); no problems.
   The downloads (COLMAP, Eigen 3.4.0, Ceres 2.2.0, glog 0.7.1, PoseLib, SQLite, all pinned by
   commit/SHA-256) were not blocked.
2. `native: WebSplat entry`: `native/entry/websplat.cc`, target `colmap_websplat`
   (`websplat-colmap.mjs/.wasm`, ES module, `ENVIRONMENT=web,worker,node`, `FILESYSTEM=0`,
   memory growth to 4 GB), plus `native/legacy313/`. All data goes through memory:
   - `ws_v_begin/image/pair/end`: verification of one pair per call with an explicit camera
     (model + params, prior focal set), COLMAP's matcher-controller semantics (fewer than
     `min_num_inliers` = 15 matches or inliers: an empty config-0 geometry), per-pair RANSAC
     seed, F/E/H/pose out.
   - `ws_m_begin/image/geometry/prepare/round/round_stats/export/end`: prior mapping. Images
     with keypoints, initial `cam_from_world` and a position prior with covariance; verified
     geometries; an in-memory SQLite database and `DatabaseCache`; the telemetry model built
     with COLMAP's own text readers (as sfm.py's `sparse/telemetry`); then per round exactly
     sfm.py `prior_mapping()`: `RunPointTriangulatorImpl` + `TriangulateReconstruction`
     (clear points, transcribe ids, fixed poses, no intrinsics; create/continue angle
     max(2, t/10), merge/complete/filter t, one global refinement; no colour extraction),
     pose-prior BA (Cauchy max(1, t/4), focal+k1 from round 1, 50 iterations, Cauchy on the
     prior positions, all images), `FilterAllPoints3D(t, 1°)`. Export: cameras/images/points3D/
     rigs/frames `.bin` into memory buffers.
   - Progress and stop: `Module.wsProgress(phase, done, total)` is called per verified pair
     batch (JS side), per triangulated image and per Ceres iteration (`check_if_stopped`); a
     truthy return stops COLMAP at its next check (`ws_m_round` returns 1).
   - `legacy313/`: COLMAP 3.13.0's two-view estimation (calibrated/uncalibrated paths,
     watermark test), its RANSAC/LO-RANSAC, five-point, 7/8-point and homography estimators,
     in `colmap::legacy313`. Why: the reference was verified by pycolmap **3.13**; COLMAP 4.2.1
     changed the estimators (tangent-Sampson E, M-estimator support, Sampson refinement, an
     H inlier floor). With 4.2.1's estimators, 8% fewer pairs verify (sample of 199 pairs: 167
     vs 182; inlier Jaccard 0.76). `legacy313/random_sampler.h` reproduces libstdc++'s
     `uniform_int_distribution<uint32_t>` (Lemire) on `std::mt19937`: emscripten's libc++
     draws different integers from the same engine, which alone made 2341 of 2698 pairs differ.
     The mapping side uses COLMAP 4.2.1 unchanged (its triangulator, mapper and option defaults
     equal 3.13's for this use; `ba_global_ignore_redundant_points3D` is false in both).

Build: `WEBSPLAT_DATA=... app/src/stages/map/build-colmap.sh` (clones and patches if the fork
is missing, runs fetch.sh/build.sh with `TMPDIR` and the build tree under `$WEBSPLAT_DATA/g2`,
copies the outputs into `app/src/stages/map/wasm/`, which is git-ignored). Clean build 5 min 40 s
(-j8), the WebSplat target alone ~20 s.

Sizes: `websplat-colmap.wasm` 6.77 MB (1.96 MB gzip -9), `websplat-colmap.mjs` 46 KB.

## JS (`app/src/stages/map/`)

- `colmap.js`: `loadColmap()`, heap transfers, progress hook.
- `features.js`: WSFT v1 decoder (CONTRACTS.md 3; stage 3 should own it once it exists).
- `verify.js`: `createVerifier()` (incremental) and `verifyPairs()`; defaults `seed: 0`,
  `legacy: true`. Output entries for `encodeGeometry()` (WSTV v1).
- `priormap.js`: `priorMap()`, `cameraFromFrames()` (sfm.py's `'%.6f'` reader camera),
  `telemetryPose()` (scipy's `from_matrix` quaternion, `'%.12g'`/`'%.9g'` as sfm.py writes
  `sparse/telemetry`; the C side prints the camera `'%.9g'` the same way), `modelJson()`.
- `map.worker.js`: module worker (verify-init / verify-batch / verify-end / map / cancel, run
  ids). `pool.js`: `verifyInPool()` (dynamic batches of 48 pairs over N workers; results are
  per-pair seeded so they do not depend on the pool) and `mapInWorker()`.

## Tests (`test/g2/`)

`run_tests.sh [--win11 CDP HTTP]` runs everything below in order (`set -euo pipefail`).
- `export_native.py`: native database → `$WEBSPLAT_DATA/g2/native/{features.bin (WSFT),
  camera.json}`. Raw matches and verified geometry are stage 4's `native_raw.bin` / `geometry.bin`.

  two_view_geometries replaced from a WSTV file (the native floor below).
- `compare_geometry.py`: pair-by-pair WSTV comparison (`--identical [--allow N]`, `--min-ratio`).
- `compare_models.py`: the G2 criteria against `ref/work/colmap/sparse/final`.
- `check_telemetry.mjs`: the JS telemetry model vs sfm.py's `sparse/telemetry/images.txt`
  (201/201 poses identical as text).
- `test_cancel.mjs`: stops between verification pairs, inside triangulation and inside BA,
  instance reusable afterwards.
- `run_node.mjs`: verify / map in Node. `run_browser.mjs` + `g2_test.html`/`g2_page.js`:
  verification in a pool of module workers and mapping in one worker, outputs uploaded to
  `$WEBSPLAT_DATA/g2/browser/<tag>/`; `--cdp` for the win11 Chrome. For win11 I used
  `test/stage4/win_chrome.ps1 start -port 9371 -name g2prof` (a private profile, so other

## Results

### 1. Verification (native keypoints + native raw matches, 3175 pairs)

Native verification itself is not reproducible: pycolmap runs it unseeded on many threads, so
the PRNG stream a pair sees depends on scheduling. Two native unseeded runs give 2715 and 2699
verified pairs (reference database: 2702); against the reference, a native rerun has identical
inliers in only 382 of 2611 common pairs (mean inlier Jaccard 0.745). With `random_seed` 0 the
native result is reproducible (two runs identical: 2698 pairs, 388344 inliers).

| | verified pairs | inliers | vs native seed 0 |
|---|---:|---:|---|
| reference database (native, unseeded) | 2702 | 388488 | - |
| native rerun, unseeded | 2715 / 2699 | 388692 / 388452 | - |
| native, seed 0 | 2698 | 388344 | (itself) |
| fork, 3.13 estimators, seed 0 (Node = Chrome) | 2698 | 388346 | same pairs, same configs; inliers identical in 2695 pairs; 3 pairs differ by 2-3 inliers (Jaccard 0.94-0.99) |
| fork, 4.2.1 estimators (199-pair sample) | 167 of 182 | -1.4% | Jaccard 0.76 |

So the fork reproduces native verification given the same seed, up to floating point: 3 pairs
with inliers at the threshold, and E in 32 pairs. F and H agree with native to 1e-6
(normalised, scale and sign removed) in every verified pair (`--model-tol 1e-6`). E differs by
more than 1e-6 in 32 pairs and by 0.11-1.41 in 8 of them (e.g. calibrated (31, 169): 0.226).
These are not rounding of one solution: E comes from the five-point polynomial roots, where
libm and the absence of FMA in wasm perturb candidate models, so RANSAC settles on a different
E. What `check_models.py` establishes is narrower than "the same optimum": every model is valid
(F rank 2; E essential to within 0.05 relative, as native's own LO-refined E deviate up to
0.02; H non-singular) and the differing E have near-equal consensus on the raw matches
(COLMAP's Sampson test at 4 px): inlier counts equal in 30 of the 32 pairs and +1 in two, but
the inlier residual sums (COLMAP's tie-break) differ by 0.64-3.27x (e.g. (14, 156): 72 inliers
each, residual sum 3.27x native's, 8 matches change membership; (31, 169): 1.29x, 2) and up to
16 matches change membership ((39, 43), a 13-inlier pair). So in these 32 pairs the fork does
not reproduce native's E, only an equally sized consensus; the reported inliers come from the
same verification and are identical except in the 3 pairs above. Mapping uses only configs and
inliers, so these E differences do not reach the model. The pairs with large E differences are
mostly weak (13-85 E inliers) or planar (config 6), where E is poorly determined. Against the unseeded reference the fork differs exactly as
much as native reruns differ from each other (337 identical pairs, Jaccard 0.744). Configs
(fork): 2: 1086, 3: 1031, 6: 581. The fork writes zero pose (qvec/tvec) where COLMAP has none
(CONTRACTS.md); the native database stores identity there.

## What remains for stages 3 and 5

- Stage 3 (features): add SIFT extraction to the WebSplat entry (upstream's `cw_extract` is
  there; set `max_num_features` 8192 and the native options) and a WSFT writer; move
  `features.js` to stage 3.
- Stage 4: run `verifyInPool` after matching (it needs only keypoints, the camera and the WSMT
  container) and write `match/geometry.bin` + `geometry.json` (record `seed: 0`,
  `estimator: colmap-3.13`, TwoViewGeometryOptions defaults). Verification time 36-70 s is
  above PLAN's 30 s (win11) / part of 1-1.5 min (laptop) for matching plus verification.
- Stage 5: `stage.js` (OPFS in/out, config keys: thresholds, prior sigma, iterations,
  estimator), progress unit `BA rounds` with per-iteration progress; checkpoint after each
  round (the round's model can be exported) if resume within mapping is wanted. Mapping is
  60-75 s, above PLAN's 20-60 s estimate; wasm SIMD (`-msimd128`) for Eigen/Ceres is the first
  thing to try (it changes summation order, so re-check against the tolerances, not bytes).
- Cancellation: without SharedArrayBuffer a running wasm call cannot see a Stop message, so
  `pool.js` stops by terminating the workers as soon as `opts.signal` aborts (also when it is
  already aborted) and rejects with AbortError; tested in Chrome (below). The `wsProgress` stop
  hook works inside triangulation and BA (tested in Node) and becomes useful with cross-origin
  isolation later. Resume after Stop means restarting the stage (or a per-round checkpoint).
- Memory budget: one mapping worker 375 MB wasm heap plus its inputs (~40 MB keypoints and
  geometry); verification workers ~35 MB heap + 35 MB keypoints copy each.

- Section 4: `geometry.json` should record the verifier (`colmap-3.13` estimators in the

## Review round 1 fixes (REVIEW-g2.md)

1. P1 Stop: `pool.js` wires `opts.signal` to `worker.terminate()` and an AbortError for both
   verification (all pool workers) and mapping, including already-aborted signals; a failing
   worker aborts the other pending calls. `g2_page.js mode=stop` tests it in real Chrome
   workers: pre-aborted verify/map, abort after 200 verified pairs, abort inside round 1's BA
   (one synchronous wasm call): rejection within 1 ms, no live workers, no messages from a
   terminated worker in the following 2 s (a running mapping worker posts BA progress every
   200 ms). Laptop and win11.
2. Models: `compare_geometry.py --model-tol` compares F, E, H normalised (scale and sign
   removed; zero vs non-zero fails), F and H must agree; `check_models.py` validates every model
   and requires each differing E to have native's inlier count within 2, reporting residual
   sums and membership changes (round 2: conclusion narrowed to "valid matrices with near-equal
   consensus", counts corrected). Both in `run_tests.sh`. Numbers and
   the explanation of the E differences are in section 1 above.
3. Notices: the fork's `THIRD_PARTY_NOTICES.md` now covers the WebSplat build and the 3.13
   port; the copied 3.13 files (`legacy313/two_view_geometry.{h,cc}`, `random_sampler.h`)
   carry COLMAP's full BSD header (folded into patch 0002). `build-colmap.sh` copies the notices,
   the colmap-wasm licence and COLMAP's `COPYING.txt` into `wasm/`; `colmap.js` exports
   `COLMAP_NOTICES` URLs so a vite build ships them (checked: the notices are emitted as an
   asset beside the wasm, the two short licences inlined as data URLs).
4. `colmap.js` `with()` allocates one argument at a time inside the try block, frees all on any
   failure and rejects null string allocations (`test_colmap_js.mjs`, mock module).
5. `pool.js`: worker `error`/`messageerror` reject the call (a module that fails to load
   rejects instead of hanging; tested), all handlers removed when a call settles. Round 2:
   workers are created inside the cleanup scope (a throwing factory terminates the ones made),
   a throwing `postMessage` and exceptions from `onProgress`/`onRound` reject through the same
   path, and any failure settles every pending call; `test_pool.mjs` (fake workers) checks each
   case for rejection, all workers terminated, no worker or signal listeners left and no
   uncaught exceptions.
6. `build-colmap.sh` refuses an existing fork unless it is the pinned commit plus exactly this
   patch series (git patch-id) with a clean tree (tested with a local edit: refused, nothing
   touched), and writes `wasm/BUILD-INFO.txt` (fork commit, patch ids, emcc 3.1.69, cmake 4.4.0,
   ninja 1.13.2, Boost 1_90, wasm sha256).
7. Criterion 3 wording narrowed (browser matching of native descriptors; browser-feature
   acceptance pending stage 3).
