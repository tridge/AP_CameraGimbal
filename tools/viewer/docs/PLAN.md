# Video flight review viewer: staged implementation plan

Build a static browser application under tools/viewer for eventual hosting at
https://firevps.tridgell.net/viewer/. Local video/log File objects never upload.
No deployment or git push is included. Preserve the existing camera application.

## Design boundaries

- A source interface emits timeline samples, decoded frames and progress; adapters
  for local files now, SupportProxy live sources later. Cancellation/generations
  prevent a previous file/seek from replacing the current frame. Workers own
  binary parsing and software decoding. Bounded Blob.slice reads and small
  decode queues; never buffer an entire multi-gigabyte input in JS or WASM.
- One normalized telemetry model retains original PTS, relative playback time,
  UTC, pose UTC, validity/provenance and missing fields. Formats: APCG JSON SEI
  in H264/HEVC MP4/TS; ST0601 KLV in MPEG-TS (including current project's private
  extensions/checksum rules). Also FFV1 gray16 thermal Matroska with APCG block
  additions, necessary for calibrated temperatures/palettes and this flight.
  No telemetry fabricated when a source lacks it. No assumption PTS equals UTC.
- Native browser/WebCodecs decoding for H264/HEVC where available; a pinned
  FFmpeg WASM worker provides FFV1 and unsupported-codec fallback. Use WORKERFS
  or equivalent File-backed seekable I/O, not writeFile of whole recordings.
  Prove FFV1 gray16 exact samples and >2GB file seeking using real flight data.
  Decode/frame-step must work without waiting for complete telemetry indexing.
- Cesium supplies coherent 2D and 3D scene modes. Adapt the mission/fence domain
  rules examined in UAVLogViewer, credit source/license where code is reused.
  Preserve MAV_FRAME global/relative/terrain altitudes; do not silently treat
  relative altitude as AMSL. Preserve polygon/circle and inclusion/exclusion
  semantics, and only connect spatial mission items. Async map/terrain replies
  cannot move a newer frame's geometry. Keyless baseline imagery and configurable
  imagery/terrain providers; browser Google Map Tiles API key slot, no hardcoded
  credentials. Aircraft AMSL vs ellipsoid/terrain datum explicitly documented.
- Optional ArduPilot BIN and timestamped MAVLink tlog parsing in workers produces
  missions, fences and actual track independently of the video's embedded pose.
  Log loading must not silently override valid camera telemetry. Keep raw clocks
  and provenance; explicit adjustable telemetry offset supports alignment.
- Review layout keeps telemetry outside image. Video play/pause/seek/frame step,
  speed, absolute UTC, source/index status and error feedback. Thermal palettes,
  auto/fixed temperature stretch and native pixel hover readings; display-only
  imagery is never mislabeled as calibrated Celsius. Mark thermal findings with
  frame/pixel/time/pose provenance and export JSON/GeoJSON. Initial thermal-peak
  assistance is a local contrast aid, not an ignition classifier.
- ES modules and narrow adapters; app state/timeline independent of presentation.
  Provider settings and review annotations local only. Accessible labelled UI,
  responsive layout, keyboard controls, no remote API required to open data.
  Runtime configuration supports /viewer hosting without rebuilding secrets.

## Stages (Claude reviews plan, then each stage; refine accepted findings)

1. Media/telemetry foundation and decoder proof: static build/dev setup, chunked
   container indexing, APCG/MISB/thermal metadata, cancellation, exact raw pixels,
   decode seek/frame step. Fixtures and real-file tests. Review before expansion.
2. Mission/log and map model: BIN/tlog mission/fence/track, explicit altitude
   frames, 2D/3D Cesium, synchronized marker/footprint/pixel picking with honest
   terrain limitations and provider configuration. Review and domain tests.
3. Integrated review UI and thermal tools: playback, sidebar, palettes, contrast,
   UTC offsets, findings and export, keyboard/accessibility/lifecycle. Review
   and refine using real flight data in Xephyr/Chrome.
4. Qualification and packaging: malformed files/unsupported codecs/log gaps,
   repeated file replacement/seek, multi-GB thermal, no-upload/network assertions,
   nested /viewer URL, screenshots in Xephyr, build and installation instructions,
   pinned dependency/license notes and final Claude review. No actual deploy.

## Acceptance evidence

- Known APCG SEI and actual MISB TS generated by this repository give matching
  telemetry fields; checksum failures and missing/invalid tag values stay invalid.
- Real streamed RGB telemetry copy plays and seeks. Real FFV1 thermal MKV retains
  raw uint16 samples, supports at least four palettes and hover temperatures.
- Small representative BIN/tlog fixtures and real flight logs produce correct
  mission/fence/track; frame3/6/10 and exclusion fences retain meaning.
- Browser automation runs in an actual Xephyr window with visible Chrome (no
  tests on the user's main desktop). Confirm WebGL 2D/3D, hover, controls and
  exports with screenshots, and no file-data upload requests.
- npm build and automated unit/integration/browser checks pass. Remaining real
  terrain, browser codec or live-source limitations are clearly documented.

## Plan review decisions and stage-0 evidence

Claude plan review completed (persistent skill session988c44c8-f336-415d-9a8e-baceff607652).

- Current KLV uses standard tags90/91, not arbitrary-angle private extensions.
  Prefer co-carried APCG SEI; invalid full-range tags never fall back to legacy.
- Domain implementation is independent of GPL UAVLogViewer source; it was read
  as a behavior reference. Explicit MAVLink/ArduPilot frame and fence semantics
  replace its lossy flattening. No source fragments copied.
- Add monotone time tie-points (import/export), keeping original UTC separate
  from corrected pose-selection UTC. Offsets alone do not repair variable clocks.
- Raw sensor orientation defaults0. Display rotation is separate; findings retain
  raw(x,y), frame ID, calibration, clock correction and terrain provenance.
- Use single-thread WASM to avoid COEP conflicts with external map tiles. Disable
  implicit Cesium ion access. Pin/package dependencies locally; all file reads
  remain local. Futurelive requires HTTPS/CORS and explicit user connection.
- Quantized terrain supplies ground picking as well as the globe. Its datum is
  explicit (plot SRTM is AMSL); no silent flat-zero or ellipsoid height fallback.
- Qualify the /viewer prefix during initial integration. Validate raw pixels and
  source clocks with Python-generated vectors and real files before UI claims.
