# AP_CameraGimbal {version} — SIYI A8 mini

Firmware: **{filename}**. Source revision: `{revision}`.
`BUILD_INFO.json` records whether the build includes uncommitted changes.

## First installation

1. Start with SIYI A8 mini camera firmware **v0.3.7** and gimbal firmware
   **v0.4.9**. Install those SIYI versions first if necessary.
2. Power off the camera and put a **FAT32 microSD card** in your computer.
3. Copy **{filename}** to the card's **top-level directory**. Keep this exact
   filename; do not copy the enclosing `A8` folder. Remove any other firmware
   update files from the card.
4. Verify the copy before ejecting the card. Its SHA-256 must match the firmware
   entry in `SHA256SUMS`. On Linux, copy `SHA256SUMS`, `README.md` and
   `BUILD_INFO.json` alongside the firmware and run `sha256sum -c SHA256SUMS`
   from the card. On Windows, use `Get-FileHash` with `-Algorithm SHA256`.
5. Safely eject the card, insert it into the powered-off camera, then power on.
   Keep power connected while the camera installs and boots. The startup
   script removes the update file after boot so the next boot does not
   install it again. Confirm it is gone before another power cycle.
6. Connect your computer to the camera's Ethernet network. For a direct
   connection, give the computer an unused address such as **192.168.144.10**
   with subnet mask **255.255.255.0**.
7. Open **http://192.168.144.25/**. Log in as **admin**, password **ardupilot**
   (unless the package builder supplied a different initial password).
8. Check the firmware version and Git hash on **Status**, then open **Live**
   to check the video. Configure the camera on **Parameters**.

The image replaces the camera application partition. It retains the bootloader,
kernel, root filesystem and gimbal firmware. A normal first installation does
not require a camera shell, telnet or a development environment.

## Updating AP_CameraGimbal from microSD

Follow the same powered-off SD-card procedure using the new release's
**{filename}**. Saved AP parameters and the web password are preserved.
The camera's Ethernet address returns to **192.168.144.25** after an application
update; reconnect there if you previously changed its network configuration.

## Updating from the ArduPilot web UI

1. Leave a writable **FAT32 microSD card** in the camera. Stop recording first.
2. Log in to the ArduPilot web UI and open **Status → Upgrade Firmware**.
3. Select **{filename}** from your computer and confirm the upload.
4. Wait for the upload-complete message. The camera writes the update to the
   card under the bootloader's required name; **uploading alone does not
   install the A8 update**.
5. Use **Reboot camera** on Status and confirm. Keep power connected during
   installation. Reconnect to **http://192.168.144.25/** and check the new
   firmware version and hash.

Older AP web builds which only accept `A8_FW_*.bin` can receive an identical
copy renamed to `A8_FW_ArduPilot.bin`; the web server saves it to the card as
`SIYI_4K_MINI_UpgradeSD.bin`. For direct SD installation, always use the original
required filename above.

## After installation

- MAVLink: TCP or UDP **16001** on fresh configurations. System ID **0** selects the first flight
  controller heartbeat automatically; a fixed ID can be set on Parameters.
- SIYI control: TCP or UDP **37260**.
- Video: `rtsp://192.168.144.25:8554/video1` and
  `rtsp://192.168.144.25:8554/video2`.
- Use **Files** to download recordings and photographs.
- If the camera application fails to start, the web UI remains available for
  **Debug**, parameter changes and **Restart camera-app**. It does not switch
  to the vendor application automatically.

To restore SIYI firmware, install the original SIYI v0.3.7 SD image using its
vendor instructions. Keep that original image available during hardware testing.

## Default changes and upgrades

Fresh configurations use MAVLink TCP/UDP **16001** and **Rate** position
tracking. Upgrades preserve saved `camera.ini` settings, including explicit
ports and `tracking_method`. Cameras configured on earlier releases can
therefore still use **14550**; check Parameters before changing the flight
controller connection.

If a saved configuration omits `mavlink.tracking_method`, it now inherits
**Rate**. Older A8, ZR10 and ZT30 templates omitted it; older MT11 templates
explicitly selected **Angle** and keep that setting. Choose **TRACK_METHOD**
on Parameters to set either method explicitly.
