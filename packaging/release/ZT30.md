## Installing from microSD

**The microSD card must be formatted as FAT32. exFAT is not supported by
the ZT30 bootloader**, even though the camera can mount exFAT after Linux
starts. The vendor startup script can delete the update file after a skipped
installation, so a missing file does not confirm that the update succeeded.

1. Back up settings and credentials if the camera already runs AP firmware.
2. Copy **{filename}** to the root of a FAT32 microSD card.
3. Power off the camera, insert the card, then power it on with reliable power.
4. Wait for installation and startup; do not interrupt power during the update.
5. Connect to the AP web interface (initial login **admin / ardupilot**) and
   check the version on **Status** and both streams on **Live**.

This is an initial installation/reinstall of the `customer` volume. It replaces
its contents, including previous AP settings, passwords and SSH identities.
It starts AP camera-app and the AP web server without vendor application fallback.
The retained `/config` SDK, sensor tuning and modules, rootfs, kernel, bootloader,
environment and gimbal firmware are not replaced. The target must match the
ZT30 runtime pinned in `packaging/zt30/platform`; this is not a vendor SDK upgrade.
After successful startup, the camera removes the SD update file to prevent a
repeated installation on the next boot.

## Updating through the web interface

The installed AP web updater must support `SIYI_ZT30_UpgradeSD.bin`. On **Status**,
select **Upgrade Firmware** and upload **{filename}**. Keep power connected and
wait for the page to reconnect and confirm the new camera and web versions.
Check both streams on **Live**.

The web path verifies the complete download and stages only the embedded
application bundle. It preserves settings, credentials, SSH access, stable
launchers and platform partitions. Failed/unconfirmed application trials restore
the previous verified AP slot. **Restore previous application** starts rollback.
Leave room for the uploaded file, a new application slot and an 8 MiB reserve.

Older AP web versions accept only `ZT30_AP_*.apbundle`. First update those once
using a newly built bridge bundle (`make zt30_package`, output under `build/`),
then use the combined `.bin` for subsequent web updates. The bridge bundle from
the same build contains the same application, web server, SDK adapter and assets.

## Validation scope

The container, checksum/failure paths, extracted customer filesystem, ARM runtime
requirements and web slot update are tested offline. FAT32 microSD installation,
subsequent cold boot and web application updates have been tested on a ZT30.
Interrupted-flash recovery has not been tested; a web rollback cannot recover
an interrupted customer-volume SD write.

Fresh defaults use MAVLink TCP/UDP **16001** and **Rate** position tracking.
Web updates preserve explicit settings in `camera.ini`.
