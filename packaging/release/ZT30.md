## Requirements

The camera must already run the AP application with the stable `zt30-slot`,
`app-init.sh`, `app-supervisor.sh` and `web-supervisor.sh` launchers supporting
web bundle upgrades. This bundle updates the camera application, web server,
SDK adapter and web assets. It preserves settings, credentials, SSH access,
launchers, retained platform libraries, kernel, bootloader and gimbal firmware.

The retained runtime must match the pinned libraries used for this build.
The installer checks their sizes and SHA-256 hashes before staging or activation.
This file is a web application bundle, not an initial SD installation image.

## Updating through the web interface

1. Verify **{filename}** against `SHA256SUMS`.
2. Connect to the camera's AP web interface and log in with your existing
   credentials (initial credentials are **admin / ardupilot**).
3. On **Status**, select **Upgrade Firmware** and upload **{filename}**.
   Keep power connected and wait for the page to reconnect and confirm the
   new camera and web bundle versions.
4. Check video on **Live** and the version/hash on **Status**.

The updater stages a verified application slot and restarts the camera and web
services. A failed or unconfirmed trial restores the previous verified AP slot.
**Restore previous application** on Status starts the same verified rollback.
Retained slots use flash space; leave room for the new bundle and an 8 MiB reserve.

For initial AP launcher installation or recovery when the web service is
unavailable, use the existing independent SSH maintenance path described in
`packaging/zt30/APP_BUNDLE.md` in the source tree. Older development launchers
need that maintenance update before they can install a bundle through the web.

## Default changes and upgrades

Fresh configurations use MAVLink TCP/UDP **16001** and **Rate** position
tracking. Upgrades preserve saved `camera.ini` settings, including explicit
ports and `tracking_method`. Cameras configured on earlier releases can
therefore still use **14550**; check Parameters before changing the flight
controller connection.

If a saved configuration omits `mavlink.tracking_method`, it now inherits
**Rate**. Older A8, ZR10 and ZT30 templates omitted it; older MT11 templates
explicitly selected **Angle** and keep that setting. Choose **TRACK_METHOD**
on Parameters to set either method explicitly.
